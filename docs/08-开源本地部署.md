# Sales 360 CRM 部署与运维

本仓库只包含 Sales 360 CRM。本地部署需要 Node.js 22、Docker Engine/Desktop 和 Compose。运行 `node scripts/init-local.mjs` 生成随机数据库及管理员密码，再运行 `node scripts/start-local.mjs`。打开 http://localhost:4300，登录只需邮箱和密码。`.env` 不会自动覆盖，也不会提交到 Git。

## 日常操作

```bash
docker compose --env-file .env -f deploy/compose.yaml ps
curl -fsS http://localhost:4300/api/v1/health
node scripts/backup-local.mjs
docker compose --env-file .env -f deploy/compose.yaml down
```

`down` 保留数据库卷；不要使用 `down -v` 删除业务数据。备份生成在忽略提交的 `backups/`。恢复前停止 API，保留一份当前库备份，然后用 `pg_restore --clean --if-exists --no-owner` 恢复可信备份。

## Cloudflare 与云服务器

`wrangler.jsonc` 为本应用独立的 Cloudflare Worker：静态前端由 Cloudflare 托管，`/api/*` 同源转发到服务器上的 API。服务器端使用独立 PostgreSQL 数据库、迁移和管理员凭据。部署前把 `FRONTEND_ORIGIN` 设为实际 HTTPS 地址，`COOKIE_SECURE=true`；在服务器上只允许可信网关访问 API，不直接暴露数据库。Cloudflare 首次发布后运行 `wrangler secret put API_ORIGIN` 写入自己的 HTTPS API 网关地址，再运行 `pnpm deploy:cloudflare`。生产 Compose 的 `API_GATEWAY_NETWORK` 必须设为网关容器所在的 Docker 网络。

每次升级前备份数据库，部署后检查健康接口、登录、核心业务写入和权限。Cloudflare 前端发布成功不代表后端已就绪；完整验收必须覆盖真实 API 与数据库。管理员可在左下角账号设置的“模型接入”中配置兼容 Responses API 的服务；密钥经服务端加密保存。部署时必须设置并长期保管 `AI_CONFIG_ENCRYPTION_KEY`，更换此密钥会使已保存的模型密钥无法读取。模型密钥不写入 Worker、浏览器或仓库。
