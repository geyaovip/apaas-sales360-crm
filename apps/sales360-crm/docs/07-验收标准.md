# 验收标准与阶段定义

“有页面”“接口返回 200”或“示例数据好看”均不足以认定业务功能完成。每条验收路径在真实前后端、持久化数据库、明确角色与可复查记录上执行。

## 第一阶段：可用 CRM 核心

| 场景 | 验收步骤 | 通过条件 |
| --- | --- | --- |
| 线索录入与分配 | 运营创建线索并分配给销售，刷新页面、重新登录 | 线索仍存在且负责人正确；分配日志、审计记录完整；非授权销售看不到详情 |
| 线索处理 | 销售接受、记录跟进、判定有效；另测退回和无效 | 只允许合法状态迁移；原因必填；时间线可追溯；主管能看团队积压 |
| 重复候选 | 使用相同注册标识或近似名称创建客户/线索 | 系统提示可见候选，不静默覆盖；跨租户数据绝不出现在候选中 |
| 线索转化 | 销售申请、主管审核，再转为客户、联系人及商机；另测拒绝、重复点击与并发重试 | 审核权限有效；拒绝原因可查；关联完整且只创建一组目标记录；同一幂等键结果一致 |
| 商机推进 | 创建商机并推进阶段，填预计金额与日期，测试赢/输单 | 规则校验有效；金额精度正确；列表与详情状态一致 |
| 跟进与待办 | 创建下一次跟进时间，等待到期并查看工作台 | 待办来自真实记录；完成后状态更新；通知失败可查且可重试 |
| 统计 | 在明确时间范围内创建、处理若干线索 | 分子分母可追溯到原始记录；处理率与导出的原始数据一致 |
| 权限 | 销售 A 尝试通过 URL/API 读取和修改销售 B 私有记录 | 服务端拒绝，列表/报表不泄漏；管理员及主管按约定范围可见 |
| 设备 | 桌面和手机浏览器完成创建、处理、转化、跟进 | 操作可完成，表单/底部动作无遮挡，空态和失败态可理解 |
| 重启恢复 | 服务与浏览器重启后重新登录 | 数据、归属、状态、审计记录持久存在 |

## 独立部署验收

空数据库启动后自动迁移并创建本地管理员；管理员可建成员，成员修改密码后旧密码与旧会话均失效。无需办公平台账号即可完成第一阶段和 CSM 业务流程。备份恢复后记录和权限仍可用。

## 第二阶段：CSM 与可选平台连接

CSM 验收：服务计划可创建、任务可分配与审核、风险可登记与关闭、续约商机能关联客户；统计能回溯原记录。健康度若上线，需显示计算口径与输入数据。

每个平台的接入单独验收，不互相借用结论：

1. 管理员授权应用，普通成员完成平台登录并正确映射到本地账号。
2. 同步成员/组织，停用或撤权后权限及时收敛。
3. 从 CRM 触发真实业务提醒，平台内实际收到，点击能打开有权限的源记录。
4. 超时、限流、令牌过期、回调重放和撤权路径有可查状态与重试/处理方案。

只有完成上述真实路径才标记该平台“已接通”；否则在产品中展示“未接入”或具体能力状态。

## 交付报告格式

每个阶段交付时记录：版本/提交、部署地址、测试角色、真实操作路径、已通过项、未通过项及限制。对外只宣称已经验证的能力，待接入和模拟数据必须明确标注。
