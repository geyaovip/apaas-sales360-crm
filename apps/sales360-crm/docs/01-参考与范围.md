# 参考与范围

版本：2026-09-25，开发前基线。

## 官方案例中可确认的内容

来源：[飞书 Sales 360 最佳实践](https://ae.feishu.cn/hc/zh-CN/articles/225702000622)，本次已查看页面文字及四张移动端展示图。

| 证据 | 对本项目的启示 |
| --- | --- |
| 案例强调多个应用、多个部门合在一个入口，主数据共享、流程衔接 | 线索、客户、商机、服务记录使用同一套业务主数据 |
| 痛点包括 MQL 分配不公平、低效及数据安全 | 分配策略、归属权限、操作留痕属于核心能力 |
| 案例列出线索流转、销售客户商机管理、CSM 管理三部分 | 产品目标覆盖销售到客户服务，但分阶段交付 |
| 首页图展示指标、常用入口、跟进记录和底部导航 | 移动端优先呈现今日工作和快速记录 |
| MQL 详情图展示线索字段、活动、评论及“无效/申请转化”操作 | 详情必须包含上下文与有条件的状态变更 |
| 商机图展示“我负责的/我参与的”、搜索及筛选 | 列表按归属和参与权限过滤 |
| 机器人提醒图展示商机提醒卡片 | 待办/提醒需有业务记录链接和发送结果 |

案例展示的“线索周处理率 46% → 84%”是原案例成效，不是本项目的目标值或承诺。案例截图中的金额、企业名与界面文案不作为本项目测试数据。

## 本项目的设计补全

官方页面不是完整 PRD，也未公开全部数据模型、状态规则、桌面端设计或三平台接入协议。下列内容是为可开发、可验收系统拟定的产品设计：

- 可审计的线索分配/领取/退回及转化规则；
- 客户、联系人、商机、活动和服务任务的数据模型；
- 桌面端响应式工作台、服务端权限与租户隔离；
- 独立登录与飞书/钉钉/企业微信适配器；
- 接口、迁移、部署、监控和验收要求。

UI 以截图的**信息层级、蓝白配色、移动端列表/详情/底部动作结构**为参考。不会把飞书商标、Logo、原文案或整张截图直接用作产品资产；具体像素及桌面布局由本项目规范定义。

## 交付边界

第一期交付真实可运行的线索到商机闭环，支持 Web 和移动浏览器。CSM 客户服务闭环与销售目标报表列入下一期，但第一期数据结构和导航不阻塞扩展。三平台均保留接入边界；每个平台是否“已接通”只由真实授权、回调和端到端验证决定。

## 开发前需由业务方确认的配置

这些问题不影响先建立产品与技术基线，实施时通过配置定稿，不应悄悄写死在代码中：

1. 客户所属行业、线索来源字典、商机阶段和输单原因。
2. 线索归属组织、自动分配范围、人工领取上限与超时规则。
3. 销售主管能否跨部门查看，以及客户重复判定字段。
4. 首个实际接入的平台及其企业管理员、应用授权范围。
5. 数据部署地区、保留期限、短信/邮件等外部通知需求。

未确认时采用文档中的默认业务规则做开发配置，并在部署前由管理员复核。
