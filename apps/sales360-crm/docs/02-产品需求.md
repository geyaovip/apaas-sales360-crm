# 产品需求（PRD）

版本：V0.1。目标是独立运行的 B2B 销售 CRM；飞书 Sales 360 是业务与视觉参考，不依赖飞书 aPaaS 作为运行时。

## 1. 产品目标与角色

核心目标：让一条线索从录入、分配、处理、转化，到客户/商机跟进都有唯一记录、明确责任人和可追溯结果。销售能在手机上完成日常处理，主管能看到真实积压与风险。

| 角色 | 主要职责 | 数据范围默认值 |
| --- | --- | --- |
| 租户管理员 | 成员、组织、角色、字典、集成配置 | 本租户全部 |
| 市场/线索运营 | 录入、清洗、分配线索，处理重复 | 本租户线索；客户仅摘要 |
| 销售主管 | 调配团队线索、查看团队商机和报表 | 本部门及下级部门 |
| 销售 | 领取与处理线索，维护客户、联系人、商机及跟进 | 自己负责或被明确加入的记录 |
| CSM | 服务任务、风险、续约（第二期） | 被分配的客户及任务 |

同一用户可有多个角色；权限由服务端按租户、角色、组织和记录归属共同决定，前端隐藏按钮不构成授权。

## 2. 首期真实业务闭环（P0）

### 2.1 线索

- 运营手动创建线索，最少填写名称或联系人、联系方式、来源、创建组织。批量导入可后置。
- 创建时服务端做规范化和重复候选提示；重复线索允许经授权确认创建，保留关联来源，不直接合并或覆盖旧数据。
- 线索池提供未分配、我的待处理、团队待处理、已处理视图，支持服务端搜索、筛选、分页。
- 运营/主管可指定分配；自动分配按**可配置的销售池和轮转策略**执行，事务内锁定候选并记分配日志，失败保留待分配状态。
- 销售可接受、退回（必填原因）、标无效（必填原因）、申请转化。默认由销售主管审核转化申请；主管可拒绝并填写原因。未经归属授权不能操作。审核是否启用按租户配置，关闭审核时由有转化权限者直接执行。
- 审核通过后，转化在一个数据库事务中创建或关联客户、创建联系人和可选商机，记录源线索 ID；重复提交只返回同一转化结果。
- 线索活动时间线记录状态、负责人、跟进与备注；普通用户不可删除审计事件。

默认状态：`new → assigned → working → qualified → conversion_pending → conversion_approved → converted`；申请被拒后 `conversion_pending → qualified`；`new/assigned/working → invalid`；`assigned/working → returned → assigned`。状态变更必须走受控命令，不开放任意 PATCH 状态。关闭审核时允许 `qualified → converted`。

### 2.2 客户与联系人

- 客户包含名称、统一标识（可选）、行业、地区、负责人、状态、来源、创建/更新时间。联系人挂在客户下，包含姓名、职务、电话/邮箱及首选联系方式。
- 客户详情聚合联系人、商机、跟进记录和活动；联系方式按权限展示，列表默认脱敏。
- 支持新增、更新、按权限转移负责人；转移后保留历史负责人和审计记录。
- 重复判断先按明确标识（如统一社会信用代码），再按规范化名称给出候选，由授权用户确认，不自动静默合并。

### 2.3 商机与跟进

- 商机必须关联客户，包含名称、负责人、参与人、阶段、预计金额与币种、预计签约日期、赢单概率、下一步行动及日期。
- 商机列表有“我负责的/我参与的/团队的”视图，搜索和阶段、客户、预计签约日期筛选。金额在服务端采用定点数，不用浮点数计算。
- 阶段默认 `发现需求 → 方案沟通 → 商务谈判 → 赢单/输单`；输单须填原因，赢单须填实际签约金额及日期。阶段字典可配置，终态不可随意回退。
- 跟进记录可关联线索、客户或商机，包含类型、正文、发生时间、下一次跟进时间；创建后可纠错但保留版本/审计。
- 到期跟进与高风险商机产生应用内待办；外部平台通知按已启用的适配器发送，失败可重试、可查发送状态。

### 2.4 工作台、报表与管理

- 工作台显示“我的待处理线索、今日跟进、逾期跟进、活跃商机、预计签约金额”等指标，全部以持久化业务数据实时聚合或可追溯的汇总表计算。
- 管理员管理成员/角色、销售池、阶段字典、通知通道；主管查看本组织线索处理率、分配均衡与商机漏斗。
- 指标定义：线索处理率 = 统计周期内有首次有效处理动作的已分配线索数 / 同期已分配线索数。展示分子、分母、时间范围；不照搬案例数值。

## 3. 后续阶段（P1）

- CSM 客户服务：服务计划、任务指派、完成/审核、风险登记、续约商机及客户健康度。健康度必须公开计算口径，不凭空生成。
- 销售季度目标、个人完成率、重点商机风险规则、客户特征对应的资料推荐。
- 经真实企业授权验证后接入飞书、钉钉、企业微信的登录、成员同步、业务消息和待办；每个平台单独报告可用能力。
- 批量导入/导出及字段级授权，依据真实业务量与权限需求排期。

## 4. 关键非功能需求

- 所有写入经过身份验证、租户和记录级授权、参数校验；敏感字段在日志中脱敏。
- 关键变更（归属、状态、金额、删除、角色）保留操作者、前后值、时间、请求 ID；常规业务数据默认软删除且需有权限。
- 操作成功返回实际持久化结果；失败明确说明能否重试。外部通知失败不回滚已提交的业务操作。
- 同一请求的重复提交、平台回调重放、任务重试不能产生重复客户或商机。
- 设计桌面与手机浏览器；移动端可完成完整线索处理、客户/商机跟进和查看待办。

## 5. 不纳入首期

报价/合同/开票/ERP 同步、AI 自动评分、自动发送客户消息、复杂营销自动化、平台原生审批、群聊机器人交互及完全复刻飞书内部 Sales 360。新增此类能力应先写业务规则与验收标准。
