# Sales 360 实施与验收记录

日期：2026-09-25。代码以本工作区为准。测试环境为 macOS 本地开发机、PostgreSQL 17、前端 4300、API 4301；非线上飞书租户。

## 已实现

- 独立 React 前端、NestJS API、PostgreSQL/Prisma 迁移、管理员引导、登录会话、组织角色与租户边界。
- 线索创建/重复候选、人工和轮转分配、接受/退回/无效、有效判定、主管审核、事务性转客户/联系人/商机、幂等键、审计时间线。
- 客户和联系人、商机阶段/输赢单、跟进与待办、工作台、按原始记录计算的销售报表。
- CSM 客户负责人分配、服务计划、任务提交与主管审核、风险登记与关闭、续约商机、服务计数报表。没有上线客户健康分；避免无依据的评分。

## 已验证

- `pnpm build:crm`：前后端生产构建通过。
- `pnpm test:crm`：真实 HTTP、角色和数据库路径通过，包含线索分配/转化、审核、重复提交幂等、客户/商机、跟进、CSM 任务审核/风险/续约、销售和 CSM 越权拒绝。测试脚本：`backend/tests/core-flow.mjs`。
- 本地验收账号覆盖线索运营、销售主管、销售、CSM。`pnpm test:local-login` 已验证四个账号的登录、角色、登出和错误密码拒绝；凭据由 `pnpm local:seed` 生成到未提交的 `review-access.txt`。
- 桌面浏览器完成新建线索→分配→接受→有效→转化申请→审核→转客户和商机；另完成 CSM 客户负责人分配，刷新后数据仍在。
- 390×844 手机视口检查登录、工作台、侧边导航、线索列表与新建表单；表单操作按钮可见。
- `pg_dump` 备份后还原到临时数据库，检查线索、服务计划、商机表可读取，随后删除临时数据库。当前环境检查时计数分别为 5、1、6，仅代表当时本地数据。

## 未完成与边界

- 飞书、钉钉、企微未完成授权、组织同步、平台登录和消息投递。平台连接状态显示“未接入”；outbox 记录不能当作已送达通知。
- 外部提醒的投递 worker、失败重试、限流处理依赖平台适配器，尚未实现。
- CRM 不处理报价、合同、开票；电子行业 ERP 在独立应用目录实现采购、销售与财务首期流程。
- 本地数据库中的浏览器验收记录和端到端测试记录是测试数据，未导入生产客户信息。
