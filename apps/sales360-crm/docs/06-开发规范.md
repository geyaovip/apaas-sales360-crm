# 开发与交付规范

## 1. 代码组织

```text
apps/sales360-crm/
  frontend/src/{app,pages,features,components,api,styles}
  backend/src/{modules,common,integrations}
  backend/prisma/{schema.prisma,migrations}
  infra/{compose,deploy}
  docs/
```

前后端分开构建和运行，共享接口类型由 OpenAPI 生成。`features/lead`、`features/customer` 等按业务领域组织；通用组件仅在第二处真正复用时抽出。其他应用不能直接引用本应用数据库表或内部服务。

## 2. 编码规则

- TypeScript 开启严格类型；禁止用 `any` 绕过业务状态和接口校验。变量、接口、数据库字段用英文，用户可见文案用中文资源文件管理。
- 后端分控制器、应用服务、领域规则和仓储；控制器只做鉴权入口、DTO 校验与调用服务，业务状态迁移写在领域层。
- 所有输入在服务端校验；所有查询强制加租户条件与记录级权限。前端校验用于体验，不能代替后端校验。
- 数据库结构改动必须提交迁移文件、回填方案和兼容说明；生产禁用自动同步表结构。
- API 变更先更新 OpenAPI/契约测试再修改前端；破坏性变更增版本或迁移客户端。
- 业务写入、审计、outbox 在一个数据库事务内完成。调用飞书/钉钉/企微 API 不放在数据库事务里。
- 集成密钥只来自运行环境的密钥配置；样例 `.env.example` 使用占位符。禁止提交 token、密码、真实客户资料或生产日志。
- 错误日志可定位请求 ID，但不得记录完整联系方式、密钥和回调明文。外部事件先验签，再解析业务内容。

## 3. 开发顺序

1. 搭建前后端、数据库、本地启动和健康检查；实现系统登录与租户/组织/角色。
2. 实现线索的录入、列表、详情、状态迁移、归属及审计。
3. 实现客户/联系人与线索事务性转化。
4. 实现商机、跟进、待办、真实工作台与报表。
5. 完成移动端布局及重要空/错/权限状态。
6. 配置真实平台应用后逐个实现与验证适配器；任何未完成平台保持“未接入”。

每一步完成后用真实数据库读写和角色账号核验，不以截图或硬编码数组充当完成证据。

## 4. 测试与质量门禁

- 单元测试覆盖状态迁移、分配轮转、转化幂等、金额/指标计算、权限策略。
- 集成测试使用真实 PostgreSQL 测试库验证迁移、事务、唯一约束、并发冲突、审计及 outbox；测试之间隔离数据。
- API 契约测试验证前端调用与 OpenAPI 一致；至少覆盖 401/403/404/409/422。
- 端到端测试以至少四类角色验证“创建线索 → 分配 → 处理 → 转化 → 建商机 → 跟进 → 工作台变化”，并验证越权、重试和平台发送失败路径。
- 前端检查手机及桌面宽度下的核心流程、键盘操作、长字段、空态、慢网与错误重试。人工验收优先观察真实浏览器行为。
- 合并/交付门禁：格式检查、类型检查、构建、数据库迁移、关键测试通过；提交说明列出功能、验证结果和已知限制。

## 5. 环境与数据

本地通过 `infra/` 的开发配置启动 PostgreSQL、后端、前端；具体命令在代码落地时写入本应用 README。开发种子数据应可显式导入和清除，且只在 development 使用。staging 使用脱敏/虚构数据，production 不自动导入样例数据。备份与回滚步骤要在首次真实部署前完成并演练。
