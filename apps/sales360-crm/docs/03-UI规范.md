# UI 与交互规范

## 1. 视觉依据与原则

参照[飞书 Sales 360 案例](https://ae.feishu.cn/hc/zh-CN/articles/225702000622)公开展示的四张移动端图：蓝白主色、清楚的页面标题、浅色分组、列表筛选、底部主操作，以及“首页 / 跟进记录 / 我的”入口。截图未展示桌面端；桌面版是本项目的响应式设计，不声称与飞书原系统一致。

原则：先让用户看清“该处理什么、谁负责、下一步是什么”。数字、状态、负责人、截止时间必须比装饰图形更易读。业务成功/失败通过明确反馈显示，不能仅靠颜色。

## 2. 设计变量（拟定）

| 类别 | 变量 | 值与用途 |
| --- | --- | --- |
| 主色 | `--color-primary` | `#3569E8`，主按钮、选中导航、可操作链接 |
| 主色浅底 | `--color-primary-soft` | `#EEF3FF`，选中行和提示背景 |
| 文字 | `--color-text` / `--color-muted` | `#1F2329` / `#646A73` |
| 背景/边框 | `--color-bg` / `--color-border` | `#F5F6F8` / `#DEE0E3` |
| 状态 | 成功/警告/错误 | `#219653` / `#B7791F` / `#D64545`，始终配文字或图标 |
| 字体 | 中文优先 | 系统字体栈：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif` |
| 字号 | 正文/辅助/标题 | `14px` / `12px` / `20–24px`；移动端正文不低于 `14px` |
| 圆角 | 控件/卡片 | `8px` / `12px`，统一四边 |
| 间距 | 4 点网格 | 4、8、12、16、24、32px，页面边距手机 16px、桌面 24px |

这些数值是实现基线，开发时用令牌集中管理；若与真实目标设备上的截图观感冲突，先更新规范再调整代码。

## 3. 信息架构

桌面端：左侧导航（工作台、线索、客户、商机、跟进/待办、报表、管理），顶部显示页面标题、全局搜索及当前组织/账号。列表与详情可两栏联动，但窄屏改独立页面。

移动端：底部“首页、跟进记录、我的”；首页卡片通向线索、客户和商机。创建跟进记录可做中央快捷入口；业务操作按钮固定于详情底部安全区域，不盖住内容。`我的`仅放个人相关内容，管理功能根据角色出现。

| 页面 | 必须展示 | 主要操作 |
| --- | --- | --- |
| 工作台 | 时间范围、指标定义入口、我的待办、最近跟进 | 进入待处理记录、创建跟进 |
| 线索列表 | 状态、来源、负责人、最近处理/超时、筛选及总数 | 创建、分配、领取、打开详情 |
| 线索详情 | 基础资料、负责人、时间线、重复提示、活动/备注 | 接受、退回、标无效、申请转化；按状态和权限显示 |
| 客户详情 | 资料、联系人、关联商机、跟进、服务摘要 | 编辑、增加联系人/商机/跟进 |
| 商机列表/详情 | 负责与参与切换、阶段、金额、预计日期、风险 | 创建、推进阶段、记跟进、标赢/输 |
| 待办与通知 | 来源记录、截止时间、当前状态、送达状态 | 打开源记录、完成或稍后处理 |

## 4. 组件与状态

- 列表：服务端筛选/排序/分页；搜索输入有清除按钮；空状态说明下一步；加载显示骨架；失败提供重试。
- 表单：必填标识、实时/提交校验、字段级错误、离开未保存提示；手机号/邮箱格式校验由前后端一致执行。
- 状态标签：固定文本和颜色映射；未知状态以中性标签显示并记录异常，不默认为成功。
- 操作确认：标无效、输单、转移负责人等显示影响及原因输入；重复提交期间禁用按钮并保留恢复路径。
- 时间线：按时间倒序显示业务事件与作者，审计事件不能由普通用户编辑；普通跟进正文纠错显示修改标记。
- 通知：应用内消息与外部平台消息分开呈现，发送失败需清晰可查，不展示假的“已发送”。

## 5. 无障碍与适配

- 桌面宽度断点拟定：`<768px` 使用单列移动布局，`768–1199px` 紧凑布局，`≥1200px` 完整桌面布局。
- 可点击目标手机至少 44×44px；键盘可达所有操作，有可见焦点；表单字段有明确标签；错误提示可被读屏读取。
- 金额、日期、时间区和币种明确显示；长文本、长公司名与大数值不得挤压主操作。
- 基于真实数据检查空、少量、大量、超长、无权限、网络慢/失败等页面状态。

## 6. 实现前视觉验收

先完成工作台、线索列表/详情、商机列表/详情的桌面与手机视觉稿或可交互页面，再按参考图比对信息层级和操作位置。参考图仅覆盖手机端的四个画面；其他页面遵循本规范，不假定存在未见的原版样式。

## 7. AI 助手补充

登录后右下角固定“AI 助手”入口，桌面打开右侧抽屉，手机打开全屏面板。面板显示当前参考业务对象、预设提问、个人历史及删除、回答来源和明确的未配置/失败状态；Esc 可关闭。建议文案标明需人工核实，不把草稿描述为已保存。
客户和商机详情增加“AI 跟进助手”卡片，摘要、待核实问题与草稿分区显示；“编辑并记录跟进”只把草稿带入原表单，用户提交前可修改。
