# 首期 API 契约草案

统一前缀 `/api/v1`，JSON 请求/响应；正式开发时由 OpenAPI 文件生成接口文档与前端类型，本文与代码需保持一致。所有路径默认要求登录，除健康检查和登录接口。租户从已验证会话确定，客户端不得任意指定 `tenant_id`。

## 1. 通用约定

- 列表参数：`page` 从 1 开始，`page_size` 默认 20、最大 100；结果含 `items,total,page,page_size`。排序字段白名单化。
- 时间使用 ISO 8601 UTC，金额在 JSON 中用十进制字符串，如 `"12345.67"`；空值用 `null`。
- 写请求接收 `Idempotency-Key`（创建、转化、分配、外部回调强制）；更新请求使用 `If-Match` 或 `version` 做乐观锁。
- 成功返回资源或结果 ID；异步外发另含 `delivery_status: pending|sent|failed`，`pending` 不代表平台已接收。
- 错误格式：`{"error":{"code":"LEAD_STATE_CONFLICT","message":"线索状态已变化，请刷新后重试","request_id":"...","details":{}}}`。状态码：400 字段错误、401 未登录、403 无权限、404 不可见/不存在、409 冲突、422 业务规则不满足、429 限流、500 服务端错误。
- 不允许“修改状态”通用接口；使用显式业务动作端点，以便集中校验和审计。

## 2. 身份与组织

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/auth/login` | 系统账号登录，建立安全会话 |
| POST | `/auth/logout` | 结束会话 |
| POST | `/auth/password` | 当前用户凭旧密码修改密码；成功后注销所有会话 |
| GET | `/me` | 当前用户、角色和组织 |
| GET | `/org-units` | 当前可见组织树 |
| GET | `/users?org_id=` | 当前可分配人员；服务端按权限过滤 |

## 3. 线索

| 方法 | 路径 | 用途与关键参数 |
| --- | --- | --- |
| GET / POST | `/leads` | 按 `scope,status,source,owner_id,q` 查询；创建包含来源、联系方式等 |
| GET / PATCH | `/leads/{id}` | 获取详情和允许编辑的字段，PATCH 需版本号 |
| GET | `/leads/{id}/timeline` | 追加式活动时间线 |
| GET | `/leads/{id}/duplicate-candidates` | 返回当前用户可见的重复候选摘要 |
| POST | `/leads/{id}/assign` | `assignee_id,reason`；人工分配 |
| POST | `/leads/{id}/accept` | 销售接受 |
| POST | `/leads/{id}/return` | `reason` 必填 |
| POST | `/leads/{id}/invalidate` | `reason` 必填 |
| POST | `/leads/{id}/qualify` | 线索判定有效，进入转化准备 |
| POST | `/leads/{id}/request-conversion` | 申请转化；审核启用时生成待审核申请 |
| POST | `/leads/{id}/review-conversion` | 主管 `decision: approve|reject`；拒绝需原因 |
| POST | `/leads/{id}/convert` | 审核通过或关闭审核后执行；`customer_id?`, `create_opportunity`, `opportunity_name?`；返回客户/联系人/商机 ID |

自动分配由管理员手动触发或后台任务触发，配置端点在管理模块；普通销售不能指定轮转目标。`convert` 必须处理同线索重试和并发。

## 5. 管理和集成

管理端点包括 `/admin/users`、`/admin/roles`、`/admin/lead-pools`、`/admin/dictionaries`。平台配置与回调单独放在 `/integrations/{platform}/...`；每个平台定义独立鉴权和验证，不使用前端传入的伪造身份。回调记录 `external_event_id` 防重放，成功响应前完成验签和持久化。

## 6. 契约验收例子

```text
POST /api/v1/leads/{id}/convert
Idempotency-Key: 9b4d...（每次用户动作生成一次）
{
  "customer_id": null,
  "create_opportunity": true,
  "opportunity_name": "产品采购项目"
}

201 Created
{
  "lead_id": "...",
  "customer_id": "...",
  "contact_id": "...",
  "opportunity_id": "...",
  "converted_at": "2026-09-25T08:00:00Z"
}
```

重复提交相同 key 与请求体返回首次结果；相同 key、不同请求体返回 409。该接口必须在同一事务内保存结果，不能出现线索已转化但无客户记录。

## 7. AI 助手（已实现）

登录后可调用 `GET /api/v1/ai/status`、`GET /ai/conversations`、`GET /ai/conversations/:id`、`DELETE /ai/conversations/:id` 和 `POST /ai/chat`。聊天请求为 `{conversation_id?, context_type: "dashboard"|"lead"|"customer"|"opportunity", context_id?, message}`；详情对象必须提供 UUID。服务端按原 CRM 读取权限获取上下文，对话仅归当前用户，回复含 `conversation_id`、`messages` 和业务来源链接。未配置模型返回 `AI_NOT_CONFIGURED`（503），模型失败返回 `AI_UNAVAILABLE`（502）。AI 不写跟进或商机。

跟进草稿：`POST /ai/follow-up-drafts` 接收 `{target_type: "lead"|"customer"|"opportunity", target_id}`，返回 `{result:{summary,questions[],draft},generated_at,source}`；`GET /ai/follow-up-drafts/:type/:id` 只读取当前用户且仍匹配业务数据快照的最近结果。草稿需在原跟进表单人工编辑后保存。
